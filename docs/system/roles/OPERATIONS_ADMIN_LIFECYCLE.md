# Operations Admin Lifecycle

## Purpose

The `operations_admin` role supports operational setup, master-data maintenance, and controlled administrative execution without requiring full executive commercial ownership.

## Typical Customer Title Mappings

- Operations Admin
- Recruitment Operations Coordinator
- Delivery Operations Admin
- Back Office Admin

## Main Responsibilities

- maintain master data
- support user setup within approved scope
- keep location and team records current
- assist with operational housekeeping
- monitor data completeness and setup issues

## Primary Records Owned Or Controlled

- locations
- teams
- users within approved scope
- client master data support entries
- portal accounts
- setup and housekeeping records

## Daily Lifecycle

### Step 1. Review setup queue

- check pending user onboarding
- check incomplete location, team, or title records
- check data-quality exceptions from core workflows

### Step 2. Support user and org maintenance

- create or update location and team records
- assign users to location and team structures
- update user status where authorized
- correct setup mistakes and incomplete references

### Step 3. Support operational master data

- update client contact records when delegated
- maintain portal-account registry
- validate that ownership fields are present on key records

### Step 4. Review data consistency

- find missing team assignments
- find missing delivery owners
- find inactive users still attached to active workflows

## Weekly Lifecycle

- review onboarding completeness
- review team membership accuracy
- review inactive or duplicate setup records
- review portal-account and master-data correctness

## Monthly Lifecycle

- review operational hygiene metrics
- review setup backlog
- archive or clean unused records where policy allows

## Key Screens And Views

- user administration
- locations and teams
- portal-account administration
- data-quality exceptions
- org setup views

## Important Handoffs

- escalates privileged access requests to `platform_admin`
- supports `client_manager` and `delivery_lead` with clean master data
- supports `recruiter` and `sourcing_support` indirectly by keeping setup correct

## Success Metrics

- onboarding completion time
- location and team setup accuracy
- low missing-owner and missing-scope errors
- low stale-master-data count

## MVP Expectations

For MVP, this role should be able to:

- manage locations and teams within allowed scope
- support user creation and assignment
- maintain portal accounts
- monitor operational setup quality
