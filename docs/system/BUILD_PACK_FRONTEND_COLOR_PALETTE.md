# MVP Frontend Color Palette

Date locked:

- Wednesday, August 19, 2026

## Purpose

This document locks the MVP visual palette for RecruitOps.

Use this across:

- Stitch foundation prompts
- Stitch page prompts
- frontend tokens
- shared components
- future refinements

The goal is to keep the product consistent, calm, and reusable.

## Palette Name

- `RecruitOps Warm Slate`

## Core Colors

- `Background`: `#F4EFE6`
- `Surface`: `#FFFDF9`
- `Surface Alt`: `#F7F1E8`
- `Surface Soft`: `#EFE6DA`
- `Text Strong`: `#273038`
- `Text Muted`: `#66706D`
- `Border`: `#D8D0C4`

## Primary System Colors

- `Primary`: `#5E7464`
- `Primary Hover`: `#516556`
- `Primary Soft`: `#D9E6DA`
- `Highlight Soft`: `#E9DFD0`

## Semantic Colors

- `Success Bg`: `#E6EFE7`
- `Success Text`: `#4F6854`
- `Warning Bg`: `#F3E7D7`
- `Warning Text`: `#9A6F3F`
- `Danger Bg`: `#F7E3E0`
- `Danger Text`: `#9B605A`
- `Info Bg`: `#E7EEEA`
- `Info Text`: `#5F6F67`

## Usage Guidance

- use `Background` for app canvas and outer shell zones
- use `Surface` for cards, tables, drawers, dialogs, and main content blocks
- use `Surface Alt` and `Surface Soft` for secondary grouped areas
- use `Primary` for main actions, selected navigation, and important emphasis
- use semantic colors for chips, alerts, warnings, validation, and state messaging
- keep borders soft and structured
- keep text contrast strong enough for long internal usage sessions

## Do Not

- do not introduce bright blue, purple, or neon brand accents
- do not mix multiple primary colors
- do not rely on heavy gradients for structure
- do not create different color systems for different modules

## Stitch Rule

Any Stitch prompt for the MVP should explicitly mention this palette and ask Stitch not to invent extra brand colors.
